# Handoff: Формула — фото-решатель задач по математике (KMP)

## Overview
Мобильное приложение под **Android, Jetpack Compose** (Kotlin, single-module или по фиче-модулям — на усмотрение проекта): пользователь фотографирует условие задачи, приложение распознаёт его (платный OCR), даёт пошаговое объяснение и, если задача этого требует, **постепенно строит график** — шаг решения подсвечивает соответствующую часть графика. Задачи без визуализации (интегралы, преобразования) используют тот же каркас, но со слотом визуализации, заменённым на подсказку.

Аудитория: школьники 7–11, ЕГЭ/ОГЭ, студенты, взрослые самоучки. Тон интерфейса: дружелюбный, лёгкая геймификация (XP, серии дней) без перегруза.

## About the Design Files
Файлы в этом бандле — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий внешний вид и поведение, а не продакшн-код для копирования. Задача — **воссоздать эти экраны на Jetpack Compose (Android)**, используя принятые в проекте паттерны и библиотеки. HTML/SVG не переносить: график рисуется на Compose `Canvas`, шрифты и цвета берутся из токенов ниже.

**Стек**: Jetpack Compose + Material 3 (компоненты берём как основу, но перекрашиваем под токены ниже — не оставлять дефолтную тему M3), CameraX для съёмки, Navigation Compose, Hilt, Coroutines/Flow, Coil для превью снимков, Room для истории, Google Play Billing для подписки. Минимальная версия SDK и Compose BOM — по настройкам проекта.

**Соответствия Compose**:
- Шторки (`3a-detail`, шторка шагов в `1b`) — `ModalBottomSheet` со своим `shape` и `containerColor`.
- Карточки — `Surface`/`Box` с `Modifier.border` и `RoundedCornerShape`, не `Card` с дефолтной elevation.
- Чипы — `FilterChip`/`AssistChip` с переопределёнными `colors`, либо простой `Box` с `CircleShape`.
- Список шагов — `LazyColumn`; раскрытие пояснения — `Modifier.animateContentSize()`.
- Нижняя навигация — `NavigationBar` + приподнятый `FloatingActionButton` камеры (`offset y = -32.dp`).
- Формулы: собственный рендер `Text` с `AnnotatedString` (надстрочные/подстрочные через `SpanStyle(baselineShift)`) либо готовый рендерер LaTeX — решить на этапе реализации.
- Edge-to-edge: `enableEdgeToEdge()`, системные вставки через `WindowInsets`; статус-бар в моках нарисован, в приложении — системный.

`Math Solver App.dc.html` открывается в браузере (нужен соседний `support.js`) — экраны интерактивны: тап «Дальше» или по шагу листает решение и достраивает график.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы и радиусы финальные — воспроизводить точно. Тексты копий — рабочие, можно править по редполитике.

## Interactions & Behavior
- **Пошаговое построение графика** — главный механизм. Шаг 1: только оси. Шаг 2: появляются корни (fade-in `opacity` 0→1, 500ms ease). Шаг 3: вершина (то же). Шаг 4: кривая прорисовывается от `stroke-dashoffset: 620` до `0`, 900ms ease (в Compose — анимировать длину пути через `PathMeasure.getSegment(0, t*length)`).
- **Двусторонняя синхронизация**: тап по карточке шага → перематывает график на это состояние; кнопка «Дальше» → следующий шаг + соответствующая анимация. Назад — состояние графика откатывается.
- Раскрытие/сворачивание пояснения активного шага — плавно (animateContentSize).
- Навигация: Камера → Проверка → Решение → (Готово / Похожая задача). История → Решение (кэш). Кнопка «?» на шаге — модалка с теорией.
- Loading: между «Решать» и решением — состояние распознавания/решения со скелетоном карточек шагов.
- Error: OCR не распознал; решатель не поддерживает тип задачи (предложить ручной ввод); нет сети.
- Responsive: базовый макет 390dp (compact width). Для expanded width (планшеты, раскладной экран) — график и шаги в две колонки через `WindowSizeClass`. Обрабатывать поворот экрана и восстановление состояния (`rememberSaveable` для текущего шага).

## State Management
Один экран решения, одна вьюмодель:

```
data class SolutionUiState(
  val problem: Problem,
  val steps: List<SolutionStep>,
  val currentStep: Int,
  val visualization: Visualization?,   // null → вариант 2a
  val isLoading: Boolean,
  val error: SolveError?
)

sealed interface Visualization {
  data class Plot2D(val expression: Expr, val marks: List<PlotMark>) : Visualization
  data class GeometryFigure(...) : Visualization
  data class AreaUnderCurve(...) : Visualization
}

// каждый шаг знает, что подсветить на визуализации
data class SolutionStep(
  val title: String, val body: String, val math: String,
  val reveal: Set<MarkId>,
  val detail: StepDetail?          // грузится лениво при открытии шторки
)

data class StepDetail(
  val rule: String,                // название применённого правила
  val why: String,                 // объяснение простыми словами
  val substeps: List<SubStep>,     // SubStep(math, comment)
  val verification: String         // проверка/подстановка
)
```
Интенты: `Next`, `Prev`, `SelectStep(i)`, `OpenStepDetail(i)`, `CloseStepDetail`, `ToggleVisualization`, `Retry`.

Ввод и гейт: `MathInputUiState(expression: ExprTree, cursor: CursorPath, tab: KeyboardTab, detectedKind: ProblemKind?, gate: ProGate?)`; интенты `Key(MathKey)`, `MoveCursor(dir)`, `SwitchTab`, `Submit`, `DismissGate`, `StartTrial`. `ProGate` показывается, когда `detectedKind` требует Pro и подписка неактивна.

Состояние — `StateFlow<SolutionUiState>` во `ViewModel`, события — `MutableSharedFlow<SolutionIntent>`; в Compose собираем через `collectAsStateWithLifecycle()`. Composable-функции без ViewModel внутри (state hoisting): экран получает `state` и `onIntent`.

Clean Architecture: `domain` (Problem, Solver use-cases, чистый Kotlin, без Android-зависимостей) ← `data` (OCR API, Room-кэш истории, биллинг) ← `presentation` (ViewModel + UiState) ← `ui` (Compose). Решатель (парсер выражения → шаги) живёт в domain и полностью тестируем без UI и без инструментальных тестов; выбор визуализации — отдельный use-case `DecideVisualization(problem, solution)`.

Ниже блок «Доступно бесплатно»: финальный ответ виден, а вывод закрыт плашкой `border: 1px dashed #D8D5CA`, фон `#FAF9F5`, замок и текст `#8A8B96`. Внизу счётчик оставшихся бесплатных задач.

**Модель визуализации** расширяется: `Visualization.GeometryFigure(primitives, labels)` и `Visualization.ForceDiagram(bodies, vectors)` — набор примитивов (отрезок, многоугольник, дуга, вектор, метка) в нормализованных координатах, приходящий от решателя/AI и рисуемый на Compose `Canvas`. Никаких картинок с сервера. Каждый шаг указывает, какие примитивы уже показаны (`reveal: Set<MarkId>`), поэтому чертёж и график анимируются одинаковым механизмом.

### 11. Pro-гейт по типу задачи (тур 6, id `6a`, `6b`)
Тип задачи определяется **до** вызова решателя и до платного OCR-запроса — use-case `ClassifyProblem(text | frame): ProblemKind`. Если kind ∈ {Physics, Geometry} и подписки нет — показываем гейт.
- **6a Ручной ввод**: чип «Похоже на физику · механика» (`#FFF0C2` / `#8A6A00`) под полем; клавиатура приглушается до `opacity .4`; поверх — затемнение `rgba(20,21,26,.55)` и тёмная шторка `#14151A` radius 32 сверху, padding 16/24/28: бейдж «PRO · AI» + подпись типа задачи, заголовок 25px/700 белым, пояснение 14.5px `#9A9BA6`, два пункта с жёлтым «★», жёлтая CTA h 56 «Попробовать 7 дней бесплатно», secondary h 50 border `1.5px solid #33343E` «Ввести другую задачу», дисклеймер 12.5px.

### 12. Сканер, переработанный (id `6c`) — заменяет экран 1c
Экран сознательно разгружен: в видоискателе нет ничего, кроме кадрирования и одной подписи. Ни вспышки, ни помощи, ни режимов съёмки, ни живых подсказок, ни линии сканирования — распознавание типа задачи происходит уже после снимка (см. `6b`).
- **Полноэкранный видоискатель**: превью камеры занимает весь экран, уходит под статус-бар и под нижнюю панель управления. Все элементы плавают поверх превью (`Box` со слоями), а не в отдельных полосах. Edge-to-edge: `enableEdgeToEdge()`, системные вставки применяются только к плавающим элементам через `Modifier.windowInsetsPadding`.
- **Кадрирование**: четыре угловых маркера 30×30, border `3px solid #FFFFFF`, скругление к внешнему углу 18; область вокруг затемнена через `box-shadow: 0 0 0 9999px rgba(15,16,22,.55)`. Рамка статична, не анимируется.
- **Единственная подпись**: «Наведите на условие», Space Grotesk 17px/600, белым, по центру над рамкой.
- **Закрытие**: круглая кнопка 40px `rgba(255,255,255,.14)` слева, под статус-баром. Других элементов управления в видоискателе нет.
- **Нижняя панель** плавает поверх превью, без собственного фона (padding 22/26/34): миниатюра галереи 52×52 radius 16 с border `1px rgba(255,255,255,.18)`; затвор — чистый белый круг 84×84 без кольца и внутренних элементов; справа 52×52 radius 16 `rgba(255,255,255,.14)` с иконкой клавиатуры → ручной ввод (5a).
- **CameraX**: `ImageAnalysis` может работать в фоне для автофокуса и оценки резкости, но **не показывает статусов в UI**. Платный OCR вызывается только после нажатия затвора; классификация типа задачи — сразу после снимка, её результат показывается на экране `6b`.

## Motion / анимации

Все длительности вынести в один объект-константу (`object Motion { const val Curve = 900; ... }`). Уважать системную настройку уменьшенной анимации (`Settings.Global.ANIMATOR_DURATION_SCALE`): при отключённых анимациях график и чертёж показываются сразу целиком, без промежуточных состояний.

**Смысловые (обязательные)**
1. **Построение графика и чертежа** — `Animatable` 0f→1f, 900 мс, `FastOutSlowInEasing`; путь рисуется через `PathMeasure.getSegment(0, t * length)`. При «Назад» анимировать прогресс до значения предыдущего шага, а не проигрывать всё в обратную сторону — состояние должно читаться как обратимое.
2. **Появление опорных точек** (корни, вершина, векторы сил, метки чертежа) — `scaleIn(initialScale = 0.6f)` + `fadeIn`, 350 мс, `EaseOutBack`. Элементы одного шага появляются по очереди с задержкой 60–80 мс, не одновременно.
3. **Раскрытие шага** — `Modifier.animateContentSize(tween(250))` на карточке, текст пояснения через `fadeIn`/`fadeOut`. Фон и рамка активной карточки — `animateColorAsState(tween(200))`.
4. **Видоискатель** (6c) — статичен: рамка кадрирования не анимируется, статусов фокуса и живых подсказок нет. Единственное движение — нажатие затвора и подъём Pro-гейта (п. 5).

**Вспомогательные**
5. **Pro-шторка** (6a, 6b) — `AnimatedVisibility` + `slideInVertically` и `fadeIn` затемнения, 300 мс; клавиатура уходит в `alpha .4` за те же 300 мс, одним синхронным движением.
6. **Камера → решение** — `SharedTransitionLayout`: снятый кадр переезжает в карточку условия. Единственный «дорогой» переход, который стоит делать: он объясняет связь экранов.
7. **XP-чип** при завершении шага — `scaleIn` + подъём на 4dp, однократно.
8. **Загрузка решения** — скелетон карточек шагов с `shimmer` 1200 мс. Никаких вращающихся индикаторов.

**Не делать**: пружинную физику на всех элементах (`spring` — только п. 2 и 7), параллакс в онбординге, любые анимации дольше 400 мс кроме построения графика (п. 1) и шиммера (п. 8).

## Accessibility
Минимальный размер тач-таргета 48dp (визуально кнопки могут быть меньше — расширять `Modifier.minimumInteractiveComponentSize()`). `contentDescription` для затвора камеры, кнопок навигации по шагам и точек на графике.
